# Role runtime

This directory contains the central provider-independent role resolver, safe invocation entry
point, and bounded asynchronous job lifecycle described by
`docs/specs/2026-07-25-arkira-role-based-realignment.md`. Workflows call `role-run.sh`; they do not
parse role configuration or provider adapters directly.

Receipt repository identity is keyed on the primary work tree, so every checkout of a repository, including a linked worktree, resolves to one identity. Primary checkout identities are unchanged by this release, so no evidence migration is required. Evidence previously written from a linked worktree under its own path is regenerated by the next certification.

Non-schema Executor dispatch is always asynchronous. The `--async` flag remains accepted for
compatibility and is redundant for Executor work. Schema-enforced structured review stays
synchronous so the runtime can validate its output. Planner and Verifier dispatch behavior is
unchanged.

## Structured review progress

Native Claude structured reviews stream content-free progress to stderr while stdout remains
one final role-result JSON document. The runtime reports elapsed time, inactivity, event count,
and a fixed phase label. It never displays reasoning, tool arguments, or event contents.

The default total deadline is 900 seconds. Explicit `--timeout` remains a hard ceiling, even
while the reviewer is active. The default inactivity limit is 120 seconds; use
`--idle-timeout` or `ARKIRA_VERIFIER_IDLE_TIMEOUT_SECONDS` to override it. Both limits accept
positive integers of at most five digits. Unknown event noise does not reset inactivity.
The final `execution.progress.termination` distinguishes `idle_timeout` from `total_timeout`;
both retain exit code 14. Cancellation and owner exit stop the provider process group.

Only one successful native terminal result followed by provider exit zero can reach schema
validation. Partial, duplicate, malformed, failed, or oversized results fail closed. Progress
is not approval. Other provider paths and asynchronous Executor jobs keep their existing behavior.

Use `job-control.sh workspace <repo>` to inspect the active Executor job or a terminal result that
has not yet been consumed or pruned. It emits one JSON document with terminal state, output and
error paths, execution identity, timing, the matching receipt path, and trailing error content. It
reconciles the resolved record exactly as `status` does, so it converges to a terminal state on its
own. The Stop hook clears a terminal workspace pointer after reporting that job once. Pruning also
clears pointers that do not name a live job. Durable records remain available through
`job-control.sh status <job-id>`.

`task-contract.sh` validates Task contract schema version 2, renders its compact Executor brief,
and exposes `bind <repo> <file>` and `load <repo> <digest>` for the immutable digest-keyed contract
store. Stored version-1 contracts remain loadable for in-flight certification. New dispatch rejects
them. Executor receipts carry the optional bound contract digest.

`harness-store.sh` captures content-addressed immutable harness snapshots under the private runtime
root and verifies every resolved load. Active goal, explicit verified rollback pin, then current installed
harness is the resolution order. A legacy repository binding is fallback only. Sync captures the verified installed snapshot before updating a
repository pin.

`goal-run.sh` binds one objective to its contract, plan, branch, HEAD, synthetic worktree tree, and
harness snapshot. `swarm-run.sh` owns isolated two-to-three-unit fan-out and atomic combined patch
integration. `preview-run.sh` owns a bounded local server process group and exact-tree UI acceptance.

`bin/arkira gate <repo> <candidate-gate-command> [args...]` is the operator surface for the
candidate gate. It resolves the verified snapshot, injects `--repo` with the resolved target
repository, and refuses an operator-supplied `--repo`. It changes no gate requirement.

Quick and Normal candidates whose exact trusted-base delta contains only regular non-executable
Markdown additions or modifications under `reports/`, `docs/specs/`, and `docs/plans/` use the
`report-only` validation shape. The shared dependency-free documentation gate runs locally and in
remote CI. Elevated, mixed, deleted, renamed, non-Markdown, and unsafe-object candidates use the
complete path.

## Task operator

`bin/arkira task <repo>` is the operator surface for Task contracts. `dispatch --contract <file>`
validates and binds the contract, renders it, applies its model and effort to that run only, and
returns the durable job ID immediately. `status <job-id>` prints a concise report. `recover` finds
the active Executor or an unconsumed terminal result for the worktree. `watch [job-id]` reports
state changes until terminal and is safe to repeat. Recovery and watch are read-only. Watch polls
every five seconds by default; `ARKIRA_TASK_WATCH_POLL_SECONDS` sets a different positive numeric
interval.

`checks [<pr-number>] [--watch]` is the read-only PR CI view. A snapshot prints one compact line.
`--watch` prints only changed check signatures until every reported check is terminal. It polls
every 15 seconds by default; `ARKIRA_TASK_CHECKS_POLL_SECONDS` sets a different positive numeric
interval. It uses only read-only `gh` calls, holds no lock, creates no job record, and gates no
merge, acceptance, certification, or publication decision. Remote CI stays authoritative. Exit
`20` reports an environment or bounded read failure. Exit `21` reports terminal failed checks,
including a failed one-shot snapshot.

Contracts with `ui.mode: browser` use the Executor `test_execution` capability. Codex uses
automatic review for that capability. The Executor requests approval only for the exact browser
or test command before its first browser launch. Other contracts continue to use sandboxed
`code_editing`. Before dispatch, the runtime checks `codex exec --help` for `--approve-for-me`.
An unsupported CLI fails immediately with a named update requirement.

The harness supplies repository access. The Executor uses repository instructions to establish
required browsers, development servers, local databases, and environment variables. It never
prints secret values. A missing prerequisite or rejected escalation must name the blocked command
and stop without retrying the browser inside the workspace sandbox.

## Native delivery recovery

`bin/arkira goal <repo> bind-delivery` binds the sealed candidate tree to its clean
final commit, exact GitHub repo/PR, requested delivery target, immutable harness,
and native goal identity. See `commands/goal.md` for arguments. `merged` needs no
Vercel call. `preview` tracks the PR head. `production` tracks GitHub's actual
merge commit and the specified Vercel project/team. READY identifies an immutable
deployment; the native owner must still verify the current production alias and
remaining acceptance criteria. A custom `scripts/deploy-production.sh` also binds
the canonical deployment workflow so a failed pre-deployment job becomes blocked.

`delivery-status` is read-only, including after completion. `recover` performs
one reconciliation. `watch` uses the existing process-group supervisor for at
most one hour. `schedule` explicitly installs a per-repository macOS launchd job
that invokes the same watcher every 30 seconds while this computer is awake.
It captures the active runtime path. No SessionStart hook installs it. Other
systems can invoke `goal watch` through their existing scheduler; there is no
cross-platform scheduler installer. Missing/terminal state removes the schedule.

The private `goals/<repo identity>/delivery.json` journal is atomically recorded
before native dispatch. It never merges or deploys. Transient provider failures
back off from 30 seconds to 15 minutes; six consecutive failures or 24 hours
become an explicit blocker. Duplicate polls share the existing ownership lock.
A crash in the native dispatch acknowledgement window blocks for inspection
rather than issuing a second turn. Inspect the bound native session, then use
`cancel-delivery` and rebind when the blocker is resolved. Cancellation stops only
the delivery worker, removes its schedule, and archives its evidence. Completed
journals remain readable and are archived when the next delivery binds.

Codex automatic delivery input requires an explicitly supplied user-owned socket
of the already loaded authoritative app-server. Native `turn/start` can steer an
active turn. Without that socket, recovery only reads the native goal and retains
ready evidence for its existing owner. It never starts another writer against
an interactive session. A native complete status must match the original goal
identity. Pause, budget limits, cleared/replaced goals, and interruptions fail
closed. `models` uses native read-only discovery and never silently falls back.

Claude recovery reads the bound installed transcript's goal-set and goal-status
records. The parser is verified against Claude Code 2.1.241, not a promised stable
public API. Unknown records fail closed. It does not cold-resume a competing
Claude process. Keep the native owner waiting on the managed watch when possible;
unattended resumption of a stopped Claude owner remains unsupported here.

Use native platform plugin installation/update, then start a new session to load
new guidance/hooks. Active goals retain their content-addressed snapshot. The
canonical callable coding guidance is `skills/coding/SKILL.md`; both platforms
read it rather than receiving copied rules. Publication, maintenance, migration,
rollback, and dashboard read contracts are in
`reports/2026-09-05-sdlc-delivery.md`.
